# PRODUCT REQUIREMENTS DOCUMENT (PRD)

## Personal Portfolio Website

### M. Azmi Al Fadillah - Frontend / Web Developer

---

## 1. Product Overview

Create a personal portfolio website for **M. Azmi Al Fadillah**, an Informatics graduate targeting professional opportunities as a:

* Frontend Developer
* Web Developer
* Junior Software Developer

The primary positioning of the portfolio must be:

> **Frontend / Web Developer**

The website should emphasize frontend development capabilities, particularly:

* React.js
* JavaScript
* Next.js
* HTML
* CSS
* Tailwind CSS

Backend technologies can be presented as supporting skills.

The portfolio is intended to be used when applying for jobs and internships, therefore it must prioritize **professional credibility, project evidence, clarity, usability, and strong visual presentation**.

---

# 2. Product Goals

The portfolio must achieve the following goals:

### Goal 1 - Clear Personal Branding

Visitors should immediately understand:

* Who the developer is
* What role they are targeting
* What technologies they primarily use

### Goal 2 - Demonstrate Technical Capability

The website must demonstrate actual development experience through real projects.

Projects should communicate:

* What was built
* Why it was built
* Technologies used
* Features implemented
* Technical challenges
* Solutions

### Goal 3 - Recruiter-Friendly

Recruiters should be able to quickly find:

* Name
* Role
* Skills
* Projects
* Experience
* CV
* Contact information

### Goal 4 - Technical Credibility

Technical users should be able to inspect:

* Project implementation
* GitHub repositories
* Live applications
* Technology stack
* Development decisions

### Goal 5 - Strong Personal Presentation

The website should feel like a real developer's portfolio rather than a generic portfolio template.

# 15. Visual Design Direction

The portfolio must feel:

* Modern
* Technical
* Clean
* Personal
* Professional
* Confident
* Interactive

The design should not resemble a generic AI-generated developer portfolio.

Avoid:

* Excessive gradients
* Purple/blue AI-style gradients
* Glassmorphism everywhere
* Floating blobs
* Excessive glowing effects
* Particle backgrounds
* Fake terminal windows
* Random 3D illustrations
* Excessive rounded cards
* Excessive animation
* Giant animated cursor

The visual identity should primarily come from:

* Typography
* Layout
* Grid
* Spacing
* Contrast
* Project screenshots
* Micro-interactions

---

# 16. Interaction Principles

Interactions should enhance usability rather than distract users.

Use:

* Smooth scrolling
* Sticky navigation
* Active navigation state
* Project hover interactions
* Button hover states
* Subtle scroll reveal
* Responsive mobile navigation

Animations should be subtle and fast.

Do not animate every element.

---

# 17. Responsive Experience

The website must provide a strong experience on:

* Desktop
* Laptop
* Tablet
* Mobile

Mobile must not simply be a compressed desktop version.

Navigation, project cards, typography, spacing, and buttons should be intentionally adapted for smaller screens.

---

# 18. Recruiter Experience

The portfolio should support the following scanning flow:

### 5 seconds

Who is this person?

### 15 seconds

What role and technologies do they have?

### 30 seconds

What projects have they built?

### 60 seconds

Can I inspect their work?

### 90 seconds

How can I contact them?

The visual hierarchy must support this flow.

---

# 19. Success Criteria

The product is successful if:

* The developer's role is immediately understandable.
* Projects are easy to discover.
* Technical skills are clearly presented.
* Project implementation can be inspected.
* GitHub and live demo links are accessible.
* CV is easy to download.
* Contact information is easy to find.
* The website works well on mobile.
* The visual design feels intentional and human-designed.
* The portfolio looks credible when presented to recruiters and technical interviewers.

---

# 20. Product Principles

Prioritize:

> Content clarity > usability > credibility > visual hierarchy > interaction > decoration

Every visual element must have a purpose.

Do not add complexity merely to make the website appear technically advanced.

The portfolio should communicate:

> "This developer can actually build web applications."

not:

> "This developer knows how to make a website sparkle."
